# K-Health 공공보건 정책 데이터 시스템 설계 v1.0
## health.hondi.net — 환자 개인 상담이 아니라, 공공 보건 현황·정책 데이터 생산 시스템으로

> 관계 문서: [`insurance/docs/PDV_INSURANCE_SYSTEM_DESIGN_v2_0.md`](../../insurance/docs/PDV_INSURANCE_SYSTEM_DESIGN_v2_0.md) · [`PDV_SANDBOX_EXECUTION_DESIGN_v1_0.md`](../../insurance/docs/PDV_SANDBOX_EXECUTION_DESIGN_v1_0.md) · [`PDV_SANDBOX_SCHEMA_v1_0.md`](../../insurance/docs/PDV_SANDBOX_SCHEMA_v1_0.md) — 이 문서는 보험 설계에 쓴 "코드를 데이터로 보낸다" 패턴을 공공보건 통계 생산에 맞게 확장한다.
> **범위 정정**: 지금까지 `health` 저장소의 `desktop.html`이 다뤄온 "개인 증상 상담·감별진단·처방 보조"는 **K-Doctor**(전문가 AI 페르소나 중 의사 페르소나)의 역할이며, 이 문서의 범위가 아니다. K-Doctor는 별도로 설계·정리된다. 이 문서가 다루는 **K-Health**는 오직 **다수의 PDV를 집계해 공공 보건 현황을 파악하고 정책 데이터를 생산하는 시스템**이다.

## 0. 왜 다시 설계하는가

`dashboard.html`은 이름과 최초 의도("국가 보건 통합 대시보드")는 이 문서가 다루려는 것과 정확히 일치했지만, 실제로는 `Math.random()`으로 지어낸 가짜 전국 통계에 실존 정부기관(보건복지부·질병관리청·국민건강보험공단) 명의를 붙인 것이었다(2026-07-26 전면 정직화 완료 — 지금은 "개발되지 않음" 안내만 표시). 이 문서는 그 자리에 **실제로 어떻게 만들어야 하는가**를 설계한다.

## 1. K-Health가 실제로 할 수 있는 일 — 법적 스코프 정정

- **감염병예방법상 실제 신고 의무 체계와는 다르다.** 특정 감염병은 의료기관이 질병관리청에 법정 신고할 의무가 있다. K-Health가 이 의무를 대신하거나 그 데이터를 자동으로 흉내 내면 안 된다 — 실제 신고 시스템과의 연동은 해당 기관과의 협의·인증 없이는 불가능하고, 지금 범위 밖이다.
- **지금 스코프는 "정책 결정자를 위한 자체 참고 통계"로 한정한다.** 실제 정부 통계를 대체·사칭하지 않고, 고팡 생태계 안에서 PDV 기록이 쌓인 사용자·의료진 표본을 기반으로 한 **독립적인 보조 지표**임을 모든 화면에 명시한다.
- **표본 편향을 항상 병기한다.** 고팡 이용자·고팡 연동 의료기관으로 표본이 제한되므로, 실제 전국 인구를 대표하지 않는다는 점을 통계마다 고지해야 한다(이전 `dashboard.html`이 전국 대표 통계인 것처럼 보였던 것과 정반대 원칙).

## 2. 이중 PDV 소스 아키텍처

보험 설계(v2.0/v2.1)는 사용자 한 명의 PDV에 코드를 보내는 단일 소스 구조였다. K-Health는 **환자 PDV**와 **의료진·의료기관 PDV** 양쪽에 코드를 보내 교차 검증한다.

```
                    ┌─────────────────────────┐
                    │   K-Health 정책 질의      │  (예: "이번 달 지역별
                    │   (코드 + 스코프 선언)     │   호흡기 질환 발생 추이는?")
                    └───────────┬─────────────┘
                                │
                 ┌──────────────┴──────────────┐
                 ▼                              ▼
     ┌───────────────────────┐      ┌───────────────────────┐
     │  환자 PDV 샌드박스 실행   │      │  의료진/기관 PDV 샌드박스 실행│
     │  (자기 보고 증상·경과)     │      │  (실제 진단·처치·처방 기록)   │
     └───────────┬───────────┘      └───────────┬───────────┘
                 │  등급형 결과만                    │  등급형 결과만
                 └──────────────┬──────────────┘
                                ▼
                    ┌─────────────────────────┐
                    │   교차 검증 · 집계 엔진     │
                    │  (환자 자기보고 vs 의료진   │
                    │   실측 기록의 일치도 확인)   │
                    └───────────┬─────────────┘
                                ▼
                    ┌─────────────────────────┐
                    │  소규모 셀 억제 (§3) 적용   │
                    └───────────┬─────────────┘
                                ▼
                    ┌─────────────────────────┐
                    │   정책 결정자용 통계 반환    │
                    └─────────────────────────┘
```

**왜 두 소스가 필요한가**: 환자 PDV만 쓰면 "증상이 있다고 느꼈다"는 자기보고에 그치고, 의료진 PDV만 쓰면 "병원에 온 사람"만 잡혀 미진료 사례를 놓친다. 두 소스를 교차하면 (a) 자기보고와 실제 진단의 격차(과잉·과소 추정 정도), (b) 진료 접근성 격차(증상은 있는데 병원에 못 간 인구) 같은, 둘 중 하나만으로는 볼 수 없는 정책적으로 훨씬 가치 있는 지표를 얻는다.

**의료진 PDV의 특수성**: 의료진은 자기 자신에 대한 기록이 아니라 **환자를 진료한 기록**을 갖고 있으므로, 의료진 PDV 샌드박스가 실행하는 코드는 "의료진 개인정보"가 아니라 "그 의료진이 처리한 익명화된 진료 이벤트 집계"만 조회하도록 캡슐 API를 설계한다(§4). 환자 식별정보가 의료진 PDV 경로로 새는 것을 원천 차단해야 한다.

## 3. 소규모 셀 억제 (Small-Cell Suppression)

공공보건 통계 고유의 위험: **"OO읍 희귀질환 환자 3명"** 같은 통계는 그 자체로 누구인지 역추정 가능한 정보가 된다. 보험 샌드박스의 "등급형 출력만 허용"(`PDV_SANDBOX_EXECUTION_DESIGN_v1_0.md` §7.1) 원칙만으로는 부족하고, 별도 규칙이 필요하다.

- **최소 셀 크기 k=5**: 지역×질병×연령대 등 임의의 교차 조합에서 표본 수가 5명 미만이면, 그 셀은 통계에서 자동으로 억제하고 "5명 미만(비공개)"로만 표시한다. 인접 상위 지역 단위(읍면동 → 시군구)로 자동 롤업(roll-up)해 대체 통계를 제공한다.
- **차분 공격 방지**: "전체 인구 - 나머지 조건 조합"으로 억제된 셀의 값을 역산할 수 없도록, 상위 집계값과 하위 셀 값이 항상 정확히 일치하지 않게 소량의 라운딩을 적용한다(controlled rounding — 예: 모든 공개 값을 5의 배수로 반올림).
- **희귀질환·낙인 질환 별도 임계값**: 성병·정신질환·특정 유전질환 등은 일반 감염병보다 낙인 위험이 크므로 k=5보다 높은 임계값(예: k=20)을 적용하고, 대상 질병 목록은 별도 검토위원회를 거쳐 정한다.
- **시계열 조합 공격 방지**: "이번 달 3명, 지난달 억제됨(5명 미만)"처럼 여러 시점을 이어 붙여 범위를 좁히는 공격을 막기 위해, 동일 조합이 억제→공개로 전환될 때 직전 값과의 차이가 일정 폭을 넘으면 한 주기 더 억제한다.

## 4. 캡슐 API 확장 — 의료진/기관 소스 키

`PDV_SANDBOX_SCHEMA_v1_0.md` §1의 키 화이트리스트 방식을 그대로 따르되, 이번엔 두 개의 소스 네임스페이스로 나눈다.

### 4.1 환자 PDV 소스 (기존 패턴)

| 키 | 반환 타입 | 비고 |
|---|---|---|
| `k-health.patient.symptom_reported_monthly` | `enum {none,mild,moderate,severe}` 지역·질병군 집계 | 자기보고, 개인 식별 불가 형태로만 |
| `k-health.patient.checkup_completed` | `bool` | 정기검진 완료 여부 |

### 4.2 의료진·기관 PDV 소스 (신설)

| 키 | 반환 타입 | 비고 |
|---|---|---|
| `k-health.provider.diagnosis_count_monthly` | `int`, 소규모 셀 억제 적용 후 5의 배수로 반올림 | ICD 대분류×지역 단위 집계만, 개별 환자 식별정보 없음 |
| `k-health.provider.bed_occupancy_rate` | `float [0,1]`, 소수점 1자리 | 기관 단위 병상 가동률 |
| `k-health.provider.avg_wait_time_bucket` | `enum {<15min,15-30,30-60,60+}` | 정확한 분 단위 대신 구간만 |

**의료진 PDV 캡슐의 추가 제약**: 환자 캡슐과 달리, 의료진 캡슐은 "이 의료진이 진료한 특정 환자 1인"을 겨냥한 조회를 구조적으로 할 수 없어야 한다 — 반환값은 항상 해당 의료진(또는 기관) 단위로 사전 집계된 값이며, 개별 환자 단위로 내려가는 조회 경로 자체를 캡슐 API에 만들지 않는다.

## 5. 교차 검증 로직 (개념)

```
자기보고 유병률(환자 PDV 집계) vs 실제 진단율(의료진 PDV 집계)
   → 격차가 크게 벌어지는 지역·질병군을 "진료 접근성 격차 의심 지역"으로 플래그

플래그 조건 (초안 — 실측 데이터로 보정 필요):
   자기보고 유병률 - 실제 진단율 > 임계값(예: 15%p) 이고
   해당 지역 표본 수가 소규모 셀 억제 기준(k) 이상일 때
```

이 교차 검증 결과 자체도 §3의 소규모 셀 억제를 통과해야 정책 결정자에게 노출된다. "격차가 있다"는 존재 여부와 대략적 규모만 보여주고, 그 이하 세부 지표는 표본이 충분히 쌓일 때까지 비공개로 둔다.

## 6. `dashboard.html`이 실제로 보여줘야 할 것 (재설계 원칙)

이전 버전의 문제는 "질병별 실시간 사망률", "AI 진단 일치율" 같은 **개별 진단 수준의 정밀 지표**를 국가 통계인 것처럼 보여준 것이었다. 새 설계는 다음 원칙을 지킨다.

1. **모든 화면에 표본 편향 고지를 상단 고정**한다 — "고팡 이용자·연동 의료기관 기반 자체 집계이며, 전국 대표 통계가 아닙니다."
2. **개별 질병 단위 정밀 지표(사망률 등)는 처음부터 다루지 않는다** — 소규모 셀 억제를 적용해도 사망 같은 낮은 빈도 이벤트는 재식별 위험이 구조적으로 높다. 정책 데이터의 단위는 "질병군(ICD 대분류) × 지역(시도 단위 이상) × 월"처럼 충분히 넓게 잡는다.
3. **"진료 접근성 격차" 같은 §5의 교차검증 지표를 핵심 대시보드로 삼는다** — 이게 바로 "환자+의료진 이중 PDV"라는 이 시스템만의 차별점이고, 기존 정부 통계(주로 의료기관 신고 기반 단일 소스)로는 보기 어려운 지표다.
4. **실시간·LIVE 프레이밍을 쓰지 않는다** — 집계 주기는 월 단위 이상으로 하고(§3의 시계열 조합 공격 방지와도 연결), "N월 기준 집계" 같은 명시적 기준 시점을 항상 표시한다.

## 8. K-Doctor와의 경계 — 재확인

- K-Doctor: 개별 환자 1명의 증상을 상담하고, 인간 의사의 진단·처치·처방을 보조. `prompts/doctor.md`에 이미 페르소나 정의가 존재하며, 이번 문서의 범위가 아니다.
- K-Health(이 문서): 개별 환자를 상담하지 않는다. 다수의 PDV(환자+의료진)를 코드 실행으로 집계해 정책 데이터를 생산한다. 사용자와 직접 대화하는 채팅 인터페이스를 원칙적으로 갖지 않는다 — 화면은 정책 결정자용 통계 대시보드여야 한다.
- 현재 `health` 저장소의 `desktop.html`/`webapp.html`에 섞여 있는 개인 상담 기능(오늘 정직화한 것)은 이 재설계가 진행되면 K-Doctor 쪽으로 이관하거나, 최소한 "이 기능은 K-Doctor입니다"라고 명확히 재라벨링해야 한다 — 이 작업 자체는 사용자가 별도로 진행하기로 했으므로 이 문서에서는 다루지 않는다.

## 9. 남은 위험과 다음 검토 항목

- [ ] 낙인 질환 목록 및 임계값(k=20 등)은 의료윤리·법률 자문을 거쳐 확정해야 함 — 이 문서의 초안 수치는 잠정치
- [ ] 의료진 PDV 캡슐 API가 "개별 환자로 내려가지 않는다"는 보장을 실제 구현에서 어떻게 기술적으로 강제할지(단순 화이트리스트만으로 충분한지, 별도 집계 레이어가 필요한지) 구체 설계 필요
- [ ] 교차 검증(§5)의 임계값(15%p 등)은 실측 데이터 없이 정한 잠정치 — 실제 파일럿 데이터로 검증 필요
- [ ] 실제 감염병예방법 신고 체계와의 관계는 법률 자문 없이 어떤 형태로든 연동을 시도하지 말 것
- [ ] `dashboard.html` 재구축은 §0의 기존 정직화 작업(2026-07-26) 위에서, 이 문서의 원칙에 따라 별도 구현 작업으로 진행
