## 1. 개요

K-Health는 고팡(Gopang) 생태계 위에서 동작하는 **AI 기반 통합 의료 서비스 플랫폼**이다. 사용자가 증상을 입력하면 AI 의사가 증상을 분석하고, 위치 기반으로 최적의 진료 기관(보건소·의원·병원·응급실)을 추천하며, 예약부터 사전 진단 요약 전송, 처방 연계, 예후 추적까지 전 과정을 자동화한다.

K-Health의 핵심 차별점은 세 가지다.

**첫째, 사전 브리핑(Pre-briefing).** AI 의사가 환자의 증상과 PDV 의료 기록을 분석하여 가능한 감별 진단 목록을 작성하고, 이를 사람 의사에게 미리 전달한다. 의사는 환자가 도착하기 전에 예비 진단을 내릴 수 있어 진료 시간이 대폭 단축된다.

**둘째, 보건소 1차 추천.** 경증 질환은 보건소를 우선 추천하여 의료 자원의 효율적 배분을 유도한다. 보건소에서 체온·혈압·심박 등 생체 정보를 추가 획득하면, AI 의사의 진단 정확도가 향상된다.

**셋째, PDV 기반 의료 기록.** 모든 진료·처방·생체 기록은 환자 본인의 PDV에 암호화 저장된다. 어느 병원을 가도 동일한 의료 기록을 활용할 수 있으며, 환자가 직접 기록을 통제한다.

### 핵심 가치 명제

| 속성 | 내용 |
|------|------|
| **진단 보조** | 증상·사진·PDV 기록 기반 확률적 감별 진단 목록 |
| **사전 브리핑** | 의사에게 환자 도착 전 AI 분석 요약 전달 |
| **보건소 우선** | 경증은 보건소→의원→병원 순 추천으로 의료비 절감 |
| **예약 자동화** | AI가 진료 기관과 협의하여 예약 완료 |
| **처방 연계** | 처방전이 약국에 미리 전달되어 대기 시간 제거 |
| **PDV 의료 기록** | 환자 본인 소유·암호화·위변조 불가 |
| **응급 연계** | 중증 판단 시 119 연결 + 앰뷸런스 자동 교통 조율 |
| **예후 추적** | 처방 이후 회복 과정을 AI가 지속 모니터링 |

## 2. 문제 정의

### 2.1 현재 의료 시스템의 구조적 문제

**진료 정보의 분절.** 환자의 과거 진료 기록이 각 병원에 분산되어 있다. A병원에서 받은 검사 결과를 B병원 의사가 참조하려면 환자가 직접 서류를 발급받아 가져와야 한다. 의사는 환자의 전체 건강 이력을 보지 못한 채 진단한다.

**초진 대기 시간 낭비.** 의사는 환자를 직접 만나기 전까지 그 환자가 어떤 증상으로 왔는지 알지 못한다. 초진 면담의 상당 부분이 기본 증상 파악에 소비된다.

**진료 기관 선택의 어려움.** 어느 병원, 어느 과를 가야 하는지 환자 스스로 판단해야 한다. 결과적으로 대형병원 응급실이 경증 환자로 포화되고, 보건소·의원이 활용되지 못한다.

**처방 대기.** 진료 후 처방전을 받아 약국에 가면 약을 조제하는 시간을 또 기다려야 한다.

**응급 상황 대응 지연.** 중증 상황에서 환자나 보호자가 119 연결과 병원 선택을 동시에 판단해야 한다.

### 2.2 K-Health의 접근법

K-Health는 AI를 **진료 전·후 전 과정의 조율자(Coordinator)**로 활용한다. 의사의 역할(실제 진단·처방·처치)을 대체하지 않고, 의사가 최선의 판단을 내릴 수 있도록 필요한 정보를 미리 준비하고 전달한다.

```
환자 증상 입력
    |
    v
AI 의사: 증상 분석 + PDV 의료 기록 참조
    |
    +-- 경증 --> 보건소 추천 --> 추가 생체 측정 --> 진단 보강
    +-- 중등도 -> 의원·전문의 추천 --> 예약 + 사전 브리핑
    +-- 중증·응급 -> 종합병원·응급실 + 119 연계
    |
    v
사람 의사: 사전 브리핑 참조 --> 효율적 진단
    |
    v
처방전 --> 약국 자동 전달 --> 환자 도착 전 약 준비
    |
    v
AI 의사: 예후 추적 --> 회복 모니터링
```

## 4. 핵심 구성 요소

### 4.1 AI 의사 엔진

K-Health의 AI 의사는 DeepSeek V3 Pro(`deepseek-chat`)를 기반으로 하며, 의료 특화 시스템 프롬프트가 주입된다.

#### 주요 기능

**증상 파악 대화.** 자연어 대화를 통해 주증상, 발현 시점, 동반 증상, 과거력, 복용 중인 약물을 체계적으로 수집한다. 사용자가 사진이나 파일을 첨부하면 시각적 소견을 추가로 분석한다.

**감별 진단 생성.** 수집된 증상 정보와 PDV 의료 기록을 종합하여 가능한 진단명과 각각의 확률을 제시한다. 단일 진단이 아닌 **확률적 다중 감별 진단** 목록으로 제공한다.

```
감별 진단 예시 (두통 + 발열 + 목 경직):
1. 바이러스성 수막염      42%
2. 세균성 수막염          28%
3. 독감(인플루엔자)       18%
4. 긴장성 두통            8%
5. 기타                   4%

-> 권장: 즉시 응급실 방문 (중증 의심)
```

**진료 기관 추천.** 감별 진단 결과와 사용자 위치를 기반으로 최적 진료 기관을 선정한다. 보건소→의원→병원→응급실 순의 단계적 추천이 기본 원칙이다.

**사전 브리핑 작성.** 예약이 확정되면 AI 의사는 의사용 사전 브리핑 문서를 자동 생성하여 진료 기관에 전송한다.

```
[사전 브리핑 형식]
환자: 홍OO (PDV L1 인증, 2601:xxxx:...)
예약 시간: 2026-06-03 14:30
주증상: 두통·발열·목 경직 (48시간 경과)
활력징후: 체온 38.9°C, 맥박 102, 혈압 118/78
감별 진단:
  1순위: 바이러스성 수막염 (42%)
  2순위: 세균성 수막염 (28%)
  -- 뇌척수액 검사 고려 권장
관련 과거력: 2025-03 편두통 진단 이력
현재 복용약: 아세트아미노펜 (일 3회)
첨부: 두통 부위 사진
AI 의사 서명: K-Health v1.0 | PDV ref: a3f2c8...
```

**예후 추적.** 처방 이후 AI 의사는 환자에게 주기적으로 상태를 확인한다. 회복이 예상보다 느리거나 증상이 악화되면 재진을 권유하고 처방을 갱신 제안한다.

#### API 호출 경로

```
클라이언트
  -> POST gopang-proxy.tensor-city.workers.dev/ai/chat
     { provider: "deepseek", system: DOCTOR_PROMPT, messages: [...] }
  -> Worker: env.DEEPSEEK_API_KEY로 DeepSeek API 호출
  -> 실패 시 Claude 폴백
  -> { content: "..." } 반환
```

### 4.2 진료 기관 네트워크

| 기관 유형 | 수 (전국) | K-Health 역할 |
|-----------|----------|--------------|
| **보건소·보건지소** | 3,500+ | 경증 1차 추천, 생체 측정 거점 |
| **의원** | 88,000+ | 일반 진료·만성 질환 관리 |
| **병원·종합병원** | 4,000+ | 중등도 이상, 전문과 진료 |
| **상급종합병원** | 45 | 중증·희귀 질환 |
| **응급의료기관** | 400+ | 응급 상황 즉각 대응 |
| **약국** | 22,000+ | 처방전 자동 수신·사전 조제 |

Kakao Maps API와 연동하여 사용자 위치 반경 내 진료 기관을 탐색한다. 거리 외에 현재 가용 슬롯, 해당 진료과 보유 여부, 실시간 대기 시간, PDV 연동 지원 여부를 종합 평가하여 추천한다.

### 4.3 PDV 의료 기록 시스템

K-Health는 `pdv.js` 모듈을 통해 모든 의료 이벤트를 환자의 PDV에 기록한다.

#### PDV 의료 기록 유형

| 이벤트 유형 | 트리거 시점 | 포함 정보 |
|------------|-----------|---------|
| `health_symptom` | AI 상담 시작 | 증상, 발현 시점, 통증 점수 |
| `health_vitals` | 생체 정보 입력 | 체온, 맥박, 혈압, 혈당, 산소포화도 |
| `health_appointment` | 예약 확정 | 기관명, 예약 시간, 진료 목적, AI 요약 |
| `health_prescription` | 처방 수령 | 약품명·용량·복용법, 처방 의사, 약국 |
| `health_diagnosis` | 진단 확정 | 진단명, ICD 코드, 담당 의사 |
| `health_followup` | 예후 추적 | 회복 상태, 증상 변화, 재진 여부 |

#### PDV 접근 제어

환자의 PDV는 환자 본인만 열람 가능하다. 진료 기관에 공유할 경우, 환자가 명시적으로 동의한 범위(진료목적·기간·기관)만 선택적으로 공개한다. 공유 동의는 앱 내 PDV 연동 바텀 시트를 통해 이루어진다.

### 4.4 생체 정보 수집 체계

**앱 직접 입력.** 사용자가 체온계, 혈압계, 혈당계의 측정값을 직접 입력한다. 웨어러블 기기와의 연동도 지원한다.

**보건소 현장 측정.** 경증 환자가 보건소를 방문하면, 보건소 측정 단말에서 생체 정보가 K-Health PDV에 직접 전송된다.

```
보건소 방문 흐름:
1. K-Health 앱에서 보건소 방문 QR 생성
2. 보건소 단말에서 QR 스캔 -> 환자 PDV 임시 연결
3. 체온·혈압·맥박·산소포화도 측정
4. 측정값 PDV 자동 저장
5. AI 의사에게 새 생체 정보 알림 -> 진단 재평가
```

#### pdv.js 생체 기록 호출

```javascript
PDV.writeVitals({
  temperature:      38.9,   // 섭씨
  heartRate:        102,    // bpm
  bloodPressure:    { systolic: 118, diastolic: 78 },
  oxygenSaturation: 97,     // %
  source:           '보건소 단말',
});
```

### 4.5 진료 예약 자동화

```
1. K-Health AI -> 진료 기관 AI 비서에게 예약 요청
   { 증상 요약, 희망 시간대, 환자 PDV 공유 동의 범위 }

2. 진료 기관 AI 비서 -> 가용 슬롯 확인 -> 예약 확정

3. K-Health AI -> 환자에게 예약 확정 알림

4. K-Health AI -> 사전 브리핑 생성 -> 진료 기관 전송

5. PDV에 예약 기록 저장

6. 예약 1시간 전 자동 리마인더 알림
```

### 4.6 처방 및 약국 연계

```
1. 사람 의사 처방 -> K-Health 수신
2. PDV에 처방 기록
3. 환자 지정 약국에 처방전 전자 전송
4. 약국 -> 조제 완료 알림 -> 환자 앱 푸시
5. 환자 도착 즉시 수령 (대기 없음)
6. GDC 약값 자동 결제
```

### 4.7 응급 대응 시스템

#### 응급 판단 기준

| 응급 신호 | 조치 |
|---------|------|
| 흉통·호흡 곤란·의식 변화 | 즉시 119 + 가장 가까운 응급실 안내 |
| 고열(39.5°C 이상) + 의식 혼탁 | 앰뷸런스 요청 + 종합병원 응급실 |
| 출혈·외상 | 119 연결 + PDV 혈액형·알레르기 전송 |
| 뇌졸중 의심(FAST 증상) | 즉시 119 + 뇌졸중 센터 안내 |

#### K-Traffic 연계

응급 판정 시 K-Health는 K-Traffic과 연계하여 앰뷸런스 또는 대체 이송 수단을 자동 조율한다. 환자 위치, 목적지, 예상 도착 시간이 119 및 응급실에 동시 전달된다.

## 5. AI 의사 시스템 프롬프트

AI 의사(DeepSeek V3)에게 주입되는 시스템 프롬프트(`prompts/doctor.md`)의 7대 핵심 원칙이다.

### 원칙 1: 안전 최우선·응급 감지

모든 대화에서 응급 징후를 우선 스크리닝한다. 흉통·호흡 곤란·의식 변화·고열+의식 혼탁 감지 즉시 119 연결을 안내하고 대화를 중단한다.

### 원칙 2: 확률적 다중 감별 진단

단일 진단을 단정하지 않는다. 가능한 진단명과 각각의 확률(%)을 함께 제시하여 사람 의사의 최종 판단을 지원한다.

### 원칙 3: PDV 의료 기록 통합

환자 동의 하에 PDV의 과거 진료 기록, 처방 이력, 생체 정보를 참조하여 개인화된 분석을 제공한다.

### 원칙 4: 보건소 1차 추천 알고리즘

```
경증 (통증 1~3/10, 활력징후 정상):    보건소 -> 의원
중등도 (통증 4~6/10, 발열 37.5~39°C): 의원 -> 병원
중증 (통증 7~10/10, 고열 39°C 이상):  종합병원 -> 상급종합병원
응급 (의식 변화·흉통·호흡 곤란):       응급실 + 119 즉시 연결
```

### 원칙 5: 진료 전 사전 브리핑 자동 작성

예약 확정 시 의사용 브리핑을 자동 작성한다. 환자 정보 마스킹(성+OO), 주증상·감별 진단·과거력·생체 정보·첨부 소견이 포함된다.

### 원칙 6: 약국 처방전 자동 연계

사람 의사의 처방이 K-Health에 전달되면, AI 의사가 가장 가까운(또는 지정) 약국에 자동 전달하여 대기 없는 수령을 지원한다.

### 원칙 7: 예후 추적 및 실시간 갱신

처방 후 1일·3일·7일·30일 주기로 상태를 확인한다. 회복 지연 또는 악화 시 재진을 권고하고 처방 변경을 제안한다.

### 의료법 준수 고지

모든 응답에 내장된 면책 고지:

> "이 분석은 AI 보조 도구의 의견이며, 의료법 제27조에 따라 실제 진단·처방·처치는 면허를 가진 사람 의사가 수행합니다. 응급 상황이라면 즉시 119에 연락하십시오."

## 12. 사용 시나리오

### 시나리오 1. 경증 — 보건소 경로

> 제주 한경면 주민이 이틀째 콧물과 가벼운 발열로 불편하다.

1. 앱 입력: "어제부터 콧물 나고 열이 조금 있어요"
2. AI 의사 추가 질문 후 체온 37.8°C 입력 → 경증 판정
3. 추천: 한경보건지소(1.2km)
4. 보건지소 방문 → 혈압·맥박 측정 → PDV 자동 저장
5. AI 의사 진단 갱신: "바이러스성 상기도 감염(감기) 78%"
6. 처방 발행 → 약국 자동 전달 → 즉시 수령

**결과**: 방문부터 약 수령까지 40분 이내.

### 시나리오 2. 중등도 — 의원 사전 브리핑

> 서울 강남 직장인이 3일째 복통과 메스꺼움이 지속된다.

1. AI 의사 상담: "복부 오른쪽 통증, 메스꺼움, 3일째"
2. 감별 진단: 충수돌기염 35% / 담석증 22% / 과민성 대장 28% ...
3. 강남 A의원 예약 확정 → 사전 브리핑 전송
4. 의사가 브리핑 참조 → 초진 5분 → 초음파 직행
5. 충수돌기염 확진 → 입원 처방 → PDV 기록

### 시나리오 3. 응급 — 119 자동 연계

> 60대 남성이 갑작스러운 흉통과 왼팔 저림을 호소한다.

1. 가족이 응급 버튼 터치
2. AI 의사 즉각 판단: "심근경색 의심 — 즉시 119 연결"
3. PDV 자동 전송: 혈액형 A+, 고혈압약 복용, 아스피린 알레르기
4. K-Traffic 연계 → 앰뷸런스 3분 거리 배차
5. 응급실 환자 정보 사전 수신 → 도착 즉시 처치 시작

### 시나리오 4. 만성 질환 — 예후 추적

> 당뇨 환자가 혈당 모니터링을 K-Health에 연동한다.

1. 혈당 측정값 매일 PDV 기록
2. AI 의사: 30일 추이 분석 → 식후 혈당 지속 상승 감지
3. "재진 권고" → 주치의에게 혈당 추이 리포트 자동 전송
4. 주치의 처방 조정 → 새 처방전 약국 자동 전달

## 13. 법적 고지 및 의료법 준수

**의료법 제27조 준수.** K-Health AI 의사는 의료행위를 수행하지 않는다. 모든 AI 분석은 의료 보조 도구의 의견이며, 최종 진단·처방·처치는 반드시 면허를 가진 사람 의사가 수행한다.

**개인정보보호법 준수.** 의료 정보는 민감 정보로서 별도의 명시적 동의 없이는 수집·처리되지 않는다. PDV는 환자 본인이 직접 통제하며, 제3자 공유는 선택적 동의가 필수다.

**응급 상황 면책.** AI 의사의 응급 판단은 보조 도구이다. 응급 상황에서는 즉시 119에 연락할 것을 권고하며, AI 판단이 늦어지더라도 119 연결을 최우선으로 한다.
